## Connection Types

{% hint style="info" %}
If you are unsure, you can use Data Stream.
{% endhint %}

<table data-view="cards"><thead><tr><th></th><th></th></tr></thead><tbody><tr><td><h4><strong>Async Comms</strong></h4></td><td><p><sub>Asynchronous, non-blocking communication where the sender doesn’t wait for a response and/or the receiver may/may not be online.</sub></p><p></p><p><sub><code>Uses Get/Put Semantics (LINK @</code></sub><code>DARIA)</code></p><p></p><p><sub><strong>When to use?</strong></sub><br><sub>Really handy if you cannot guarantee both the sender/receiver will be online at the same time.</sub></p><hr><p><sub><em><strong>Example:</strong></em></sub><br><sub><em>A device uploads data that is processed later, or a message is delivered when the recipient comes online.</em></sub></p></td></tr><tr><td><h4><strong>Sync Comms</strong></h4></td><td><p><sub>Synchronous communication where the sender waits for an immediate response.</sub> </p><p></p><p><sub><code>Uses Get/Put Semantics (LINK @</code></sub><code>DARIA)</code></p><p></p><p><sub><strong>When to use?</strong></sub><br><sub>You need real-time interaction or confirmation.</sub></p><hr><p><sub><em><strong>Example:</strong></em></sub><br><sub><em>A user request that must return a result immediately, like fetching account details.</em></sub></p></td></tr><tr><td><h4><strong>Notifications</strong></h4></td><td><p><sub>One-way signals used to alert or inform.</sub></p><p></p><p><sub><code>Uses the 'Notification' semantic</code></sub></p><p><br><sub><strong>When to use?</strong></sub><br><sub>You need to notify without requiring a response.</sub></p><hr><p><sub><em><strong>Example:</strong></em></sub><br><sub><em>Push notifications, system alerts, or status updates sent to users or services.</em></sub></p></td></tr><tr><td><h4><strong>RPC</strong></h4></td><td><p><sub>Remote Procedure Calls.</sub></p><p><sub>Structured request/response interactions between systems.</sub> </p><p><sub>For a complex job; not sure when the other party will be online. (<strong>Particularly good for policy</strong>)</sub></p><p></p><p>In the SDK (colin will give me the link)</p><p><sub><strong>When to use?</strong></sub><br><sub>You want function-like calls across services with clear inputs and outputs.</sub></p><hr><p><sub><em><strong>Example:</strong></em></sub><br><sub>Calling a billing service to calculate charges or a policy engine to validate access.</sub></p></td></tr><tr><td><h4><strong>Data Stream</strong></h4></td><td><p><sub>Continuous or high-frequency data flow.</sub></p><p></p><p>Uses the stream semantic.<br>Useful for LLM and you are not sure when it will be finished.</p><p><sub><strong>When to use?</strong></sub><br><sub>You’re handling live, ongoing data rather than discrete messages.</sub></p><hr><p><sub><em><strong>Example:</strong></em></sub></p><p><sub><em>Telemetry feeds, sensor data, logs, or real-time analytics pipelines.</em></sub></p></td></tr><tr><td><h4><strong>TCP</strong></h4></td><td><p><sub>Low-level, persistent network connections.</sub><br><br><sub>Lower latency (ex: noports SSH, MCP server etc).</sub></p><p></p><p><sub><strong>When to use?</strong></sub><br><sub>You need full control over transport or are modeling underlying network behavior.</sub></p><hr><p><sub><em><strong>Example:</strong></em></sub></p><p><sub>A custom protocol, legacy integration, or long-lived secure connection.</sub></p></td></tr></tbody></table>
